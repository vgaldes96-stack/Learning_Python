Create a downloadable PDF containing structured learning notes for today’s Python session.

- **Week:** [insert week number]
- **Lesson:** [insert lesson number]
- **Session date:** [use today’s date]
- **Time zone for the creation timestamp:** Europe/Malta
- **Current stage of the learning plan:** [very brief description]

## Purpose

This PDF should be a clear and reliable study resource, not a transcript of the conversation. Summarise what I learned, the exercises completed, the difficulties encountered and the corrections made. Preserve enough detail for me to revise the material independently later.

Base the notes only on information genuinely available in this conversation and any learning documents I have attached. Do not invent topics, exercises, explanations, progress or earlier learning.

## Required PDF structure

Include:

1. A clear title containing:
   - **Python for Data Analysis**
   - **Week [number]**
   - **Lesson [number]**
   - A short descriptive lesson title

2. The date and time the PDF was created, using the Europe/Malta time zone.

3. A table of contents with accurate page references.

4. Clearly numbered headings and subheadings.

5. Page numbers on every appropriate page.

6. A brief session overview explaining:
   - What the session covered
   - How it relates to the wider learning plan
   - The main learning outcome

7. Detailed notes on each concept covered during this session.

8. A **Key terminology and definitions** section. Define important terms in accessible language and include a short example where useful.

9. A **Code examples** section containing:
   - Clean and corrected versions of important code
   - Brief comments where these support understanding
   - The expected output, where known
   - An explanation of what each example demonstrates

10. An **Exercises and corrections** section covering:
    - The tasks attempted
    - My original difficulty or error, where relevant
    - Why the problem occurred
    - The corrected approach
    - The general lesson to remember

11. A **Common mistakes and reminders** section based on issues that arose during the session.

12. A **Current-session checklist** showing which skills were introduced, practised or demonstrated during this lesson.

13. A **Cumulative learning-plan checklist** summarising what I have learned so far across the whole Python-for-data-analysis learning plan. Organise it by topic or learning stage and use these labels:
    - **Learned and demonstrated**
    - **Practised but needs reinforcement**
    - **Introduced but not yet practised sufficiently**
    - **Not yet covered**

14. A short **Recommended next steps** section based on my demonstrated progress. Clearly distinguish revision from new material.

## Evidence and accuracy requirements

- Distinguish between something that was merely explained and something I demonstrated successfully in an exercise.
- Do not mark a skill as learned solely because it was mentioned.
- Preserve any important misunderstandings, corrections or questions because these indicate what may require further practice.
- If code was corrected during the session, show the final working version and briefly explain the correction.
- Do not claim that code produced a particular result unless that result is available or can be determined reliably.
- Maintain continuity with earlier lessons where the relevant information is available.
- If the available conversation does not contain enough evidence to reconstruct the cumulative learning checklist accurately, say so clearly. Include only the progress that can be verified and identify what earlier information or document would be needed to complete it.
- Do not silently guess missing lesson details.

## Presentation requirements

- Use accessible language suitable for a beginner who is learning Python for data analysis.
- Keep technical terminology where it is useful, but explain it clearly.
- Format Python code in distinct, readable code blocks using a monospaced font.
- Use tables only where they improve clarity.
- Ensure headings, tables and code blocks do not overlap, split awkwardly or extend beyond the page margins.
- Keep the layout professional, uncluttered and consistent.
- Generate the PDF, render it to check every page visually, and correct any formatting or pagination problems before providing the final downloadable file.

## Token and context management

Use the available context efficiently. Do not reproduce the conversation or include repetitive explanations.

If the conversation is long or the available context is limited, prioritise:

1. Concepts taught in the current session
2. Exercises I attempted and the final corrected code
3. Errors, misunderstandings and explanations that affected my learning
4. Evidence of what I can now do independently
5. Unresolved questions or areas requiring reinforcement
6. Cumulative progress that can be verified from the available context
7. Recommended next steps

Compress repeated discussions into one accurate explanation. Retain distinct corrections when they teach different lessons.

If important context appears to be missing, do not compensate by inventing information. State the limitation briefly in the PDF and ask me for the previous notes or learning handover only if these are necessary for an accurate cumulative checklist.

## Final checks

Before providing the PDF, confirm internally that:

- The correct Week and Lesson Number appear in the title
- The table of contents and page numbers are accurate
- The creation date and time are included
- All important terminology from the session is defined
- Code is syntactically correct to the best of the available evidence
- Current-session learning is distinguished from cumulative progress
- The checklist reflects demonstrated learning rather than assumptions
- No unsupported content has been added
- The final PDF has been visually inspected

Provide the completed PDF as a downloadable file. Keep the accompanying message brief.
